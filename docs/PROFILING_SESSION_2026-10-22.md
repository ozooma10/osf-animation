**OSF Animation profiling session — October 22, 2026**

The best optimization target is the catalog pipeline. With 952 authored scenes from 38 files, reloading content cost **287–291 ms** and triggered a **185–189 ms game-thread browser refresh task**. That task transfers a **6.13 MB catalog** even when the browser is closed. Steady playback was inexpensive: eight synchronized AF actors used approximately **0.104–0.105 ms of instrumented elapsed time per update interval**, including work across threads. This is not a measured rendered-frame critical-path cost or a promised FPS improvement.

No production implementation was changed. **Recommended work, in priority order.** These are measured subsystem costs and source-backed implementation candidates. Savings have not been demonstrated by an optimized build.

1. **Avoid the full catalog round trip for background duration scanning.** Each reload posted a browser frame task with a maximum duration of **185.3–188.8 ms**. Inside it, `API.ReadCatalog` took **145.9–153.1 ms**, involving **736,334 tracked allocations**, and `API.Send.Bytes` reached **6,126,002 bytes**. The trace places this work on `Game Main`. `ContentReloaded` posts `CatalogData::Clips()`, which calls `Refresh()` and obtains/deserializes the complete catalog before returning the clip list. The browser was closed during both measurements. First consider a content-neutral, compact clip-candidate read or an immutable catalog representation prepared outside the frame drain. Keep duration values separate from static registry metadata and preserve registry revision/ownership semantics. Deferring the same full refresh until the browser opens merely moves the hitch. Sources: [reload subscriber](../extensions/browser/src/API/UIBridge.cpp), lines 1234–1238; [catalog refresh](../extensions/browser/src/API/EngineClient.cpp), lines 47–61 and 74; [ReadCatalog/Send](../src/API/EngineServices.cpp), lines 31–49. Validate with the same two reload captures and a fresh browser-open scenario after implementing a candidate.

2. **Reduce the derived clip provider's full-catalog conversion and sort work.** `API.ClipProviderRebuild` took **170.5–176.9 ms**, with **687,371 tracked allocations**. It ran on a job thread in the reload captures, separate from the game-thread refresh above. Subtracting its instrumented catalog-builder child leaves **150.6–157.0 ms** of self elapsed time, which includes serialization, the addon callback, and response decoding—not a proven single leaf bottleneck. The implementation builds a complete typed catalog, converts it to JSON, serializes it, parses it into another typed catalog in Browser, builds the derived entries, and converts the result back through JSON. Browser's clip sort also repeatedly lowercases source IDs and filenames in its comparator. Start with precomputed sort keys and a narrower provider input; then assess whether static catalog data can be reused safely. `PublishProviders` additionally copies the base snapshot. Preserve authored-ID precedence, deterministic derived IDs, old snapshot pinning, and callback lifetime contracts. Sources: [provider bridge](../src/API/EngineServices.cpp), lines 145–165; [BrowserClipLibrary](../extensions/browser/src/API/BrowserClipLibrary.cpp), lines 13–61 and 77–86; [snapshot publication](../src/Registry/ContentProviders.cpp), lines 31–38. The **287–291 ms reload** and the **185–189 ms later frame task** are separate measured operations; do not present nested/overlapping scope totals as additive CPU time.

3. **Trim resource probing during reloads and duration scans.** `Registry.LoadAll.SweepClips` took **37.0–39.5 ms** and **215,238 tracked allocations** per reload. A warm archived AF duration probe still spent **16.8–16.9 ms** in `Import.Ba2.ReadArchive`; there were two duration probes in each captured reload. The loose-AF path already reads only the 64-byte header. The archive fallback reads the archive resource before checking whether the previous cached duration is unchanged. Consider caching an archive name/record index and validating archive identity before loading/decompressing unchanged bytes. Preserve fresh checks for changed loose files and changed archives. Sources: [availability sweep](../src/Registry/ContentRegistry.cpp), lines 2449–2454; [duration probe](../src/Serialization/ClipDurationProbe.cpp), lines 234–257; [BA2 reader](../src/Util/Ba2.cpp). This is a background/startup improvement; it was not a sustained playback bottleneck.

4. **Precompute invariant additive-pose math if additive density grows.** `Anim.Stamp.Write` used **88.95 ms over 21.13 s**, or **17.54 µs per actor stamp**, in the two-actor additive case. Ordinary two-actor override writing was about **2.63 µs per stamp**. Additive writing accounts for roughly **83% of StampPose's inclusive time** in that workload. `WriteAdditive` converts the unchanged reference matrix to a normalized quaternion and inverts it for every driven bone on every stamp. A cached inverse reference rotation is a narrow candidate; avoiding unnecessary sampled quaternion→matrix→quaternion conversions is a larger follow-up. Preserve live-base generation checks, row/column conventions, rest-pose no-op behavior, weights, padding, and scale. Sources: [additive loop](../src/Animation/Graph.cpp), lines 617–636; [WriteAdditive](../src/Animation/PoseMath.h), lines 242–276. Absolute cost remains small: eliminating the entire measured write scope would save only about **4.2 ms/s**, not milliseconds every frame. Use the additive-math suite plus rendered transition/additive acceptance for any change.

5. **Reduce cold GLB sanitization work without losing exporter compatibility.** The sampled GLB's cold `Load.Clip` cost **4.52 ms**, versus approximately **0.01 ms** warm. `Import.GLTF.Sanitize` alone cost **1.39 ms** and **10,558 of the loader's 10,718 tracked allocations**; the subsequent fastgltf parse was **0.40 ms**. The sanitizer parses and reserializes the JSON and reconstructs the GLB buffer. A validated fast path for already-compatible input or a less copying repair path could reduce first-use latency. Keep repair support for malformed exporter accessor bounds, gzip handling, and malformed-input limits. Source: [GLTF import](../src/Serialization/GLTFImport.cpp), lines 127–235. Cache hits already avoid the resource read on the tested resource path; that older proposed optimization is already present and worked here. Source: [clip loader](../src/Animation/GraphManagerClipLoad.cpp), lines 171–210.

6. **Treat global hook membership filtering as a later density optimization.** In the dense steady capture, **41,888 of 47,124 graph updates were misses (88.9%)**. Trace attribution found **11,056 misses** for each hook: graph-update misses averaged **0.842 µs**, and compose misses averaged **0.662 µs**. Together they cost **16.64 ms over the 7.04 s trace**, approximately **2.36 ms/s**. This proves avoidable work, but its measured size does not justify a risky lock/ownership redesign first. An immutable membership lookup could be evaluated if real populated-world captures demonstrate a larger problem. Keep existing revalidation and reclamation guarantees. Source: [global hooks](../src/Animation/GraphManager.cpp), lines 1570–1634. The missing-target recovery path was not reproduced as a sustained hotspot in this session.

**Areas that do not currently justify priority changes.** Warm transition preparation stayed small: the effects window had 21 coordinator ticks totaling 2.71 ms, with a maximum of 0.176 ms; warm clip loads totaled 0.15 ms. Its 206 Papyrus event deliveries totaled 3.50 ms, and 20 audio worker jobs totaled 0.14 ms. Equipment preparation's `ApplyPlan` took 1.46 ms, mostly eight actual `SetWorn` operations totaling 1.40 ms; 36 actor-state inventory reads totaled approximately 0.03 ms. The actor-state ownership/reconciliation checks are not an optimization target on this evidence. Scene-orbit camera ticks averaged **6.51 µs**. Single-actor matchmaking returned 100/100 matches at **93.77 µs/query**; two-actor queries returned no compatible candidates at **91.40 µs/query**. The latter measures the negative-query path, not successful two-actor binding/permutation cost.

The recovered quiescent save/load completed. `Persist.WriteSidecar` took **6.44 ms**, predominantly **6.22 ms in SaveAtomic**; serialization itself was about **0.002 ms**. Loading the sidecar took about **0.245 ms**. The save had no client records, so this does not characterize large persistence payloads or active-scene save behavior. During load, 25,941 form-delete sink calls totaled 3.39 ms; high call count alone does not make this a significant bottleneck.

**Profiler overhead and interpretation.** The engine-free profiler suite passed. Its measured scope costs were **0.73 ns off, 35.29 ns stats, 37.04 ns trace** on this machine. Eight-actor steady mode comparisons used off→stats→trace→stats→off→trace. All six windows had a mean hook interval near 8.333 ms and p99 intervals of 8.81–8.91 ms. Warm stats reported 0.104–0.107 ms OSF/hook and warm trace about 0.107 ms. Whole-process CPU samples varied enough that they do not establish a precise overhead percentage. Off mode still uses the profiling binary; there was no shipping-DLL/WPR A/B or uncapped presentation test.

The first trace window on each fresh process includes lazy ring allocation. With the deliberately large 1,048,576-event rings, the first two-actor trace showed individual **4–5 ms** scope spikes and an OSF/hook maximum of **14.88 ms**. The same first-use effect appeared in the camera trace. These are collector warm-up effects, not production animation regressions. Warm traces and stats are used for ranking. Prewarm the rings or discard a warm-up window before future latency comparisons. Snapshot-copy time is also logged separately and must not be counted as production work.

**Retained failures and coverage limits.** The original main controller stalled serializing a PowerShell `FileInfo` after the save was written, before issuing load. Its process identity was verified and that controller alone was stopped. The failure and stall-window capture were retained; a bounded metadata observation then completed a fresh save/load capture in the owned game. The camera supplement subsequently timed out because its matcher observation incorrectly required every query to succeed; all 100 two-actor queries had returned a valid no-match result. A separate corrected query run captured both batches. Neither original controller run is relabeled as a clean pass. These were measurement-controller failures, not observed game crashes.

The audio fixture was silent PCM. The engine logged its existing listener fallback for a requested role emitter, so native positioned audio was not validated. The session did not profile visible browser JavaScript/layout/GPU rendering, physical camera input, a populated retail city, many concurrent independent scenes, large third-party equipment/persistence providers, or a broad clip corpus. No WPR CPU sampling, rendered-FPS claim, visual acceptance, or production optimization A/B is included. Library-build and additive-math leaf recommendations should be narrowed with additional instrumentation/sampling before large refactors.
