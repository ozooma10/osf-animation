# Changelog

All notable changes to OSF Animation are documented here.

## [1.5.0] - 2026-07-31

### Fixed
- **A model-update hook no longer loses Starfield's output-transform argument.** The bad forward could make the engine write through an invalid destination during ordinary actor model updates, even before an OSF scene started.
- **Alternative equipped-armor prop keywords no longer create false warnings.** A prop source may name several keyword editor IDs as any-of fallbacks; an unavailable alternative is now author-debug detail, while a warning is reserved for the action actually failing to resolve a source.
- **Masked and additive playback no longer flashes back to the full vanilla pose during a live actor-3D rebuild.** When equipment or cosmetic visibility replaces the current model node between animation evaluation and composition, the compose hook now verifies the new node against the managed actor, rebuilds the bone binding, and stamps that same pass instead of waiting several frames for a later animation update.
- **Sound authoring now describes what the engine actually does.** OSF's current Wwise external-source route posts at the listener and cannot apply per-cue volume, so the inert position/volume plumbing and misleading schema claims were removed. `role` still selects the voice channel, `{gender}` substitution, and subtitle speaker; legacy `volume` keys remain harmless unknown data.
- **Background scans and health diagnostics now have safe ownership boundaries.** Detached duration/audio jobs retain process-lifetime state through shutdown, registry traversal reports root-relative labels, health context strips quoted absolute paths defensively, and Data-relative clip resolution now follows Windows case-insensitivity without rejecting legitimate names that begin with two dots.
- **Scene track dispatch now stays typed after import.** Authored action and camera identifiers are parsed once into enums instead of being repeatedly lowercased and compared during playback, while the browser's duplicated animation-keyword label formatter is now one tested helper.
- **One-shot scenes no longer snap back to the clip's first frame at the end.** A final stage finishing by loop count (including the untimed play-once default) reset the scene clock to zero while the deferred stop crossed to the game thread, so the cast flashed the clip's *start* pose — for an equip-style gesture, near-vanilla arms — for anywhere from one frame to a quarter second of task-queue jitter, and the fade-out then blended from that wrong pose (wrapping onward as it ran). The scene now holds the clip's **final** frame through the stop window, and the fade-out samples that held end pose instead of wrapping. This was the "sporadic one-or-two-frame snap" visible at the end of masked upper-body transitions.
- **Two more rare one-frame pose snaps during masked/partial-body playback.** An in-place skeleton mutation (helmet-visibility patches or prop geometry changing the node table *without* replacing the model node) could leave one compose stamping a stale binding into remapped rig slots; the stamp now detects the changed node-table identity and re-binds on that same compose. Separately, the feathered-seam/additive live base could be recaptured from OSF's own previous write when a compose repeated without a fresh engine evaluation, popping the spine as it re-blended over itself; the capture now verifies the buffer actually changed since our last stamped write (a probe of the last written slot) before adopting it. Both formerly-silent paths — plus mid-play same-node re-binds and failed compose recoveries — now emit rate-limited trace diagnostics.
- **The feathered spine seam keeps its live base through a compose-time rig rebuild.** Helmet visibility and other equipment changes can rebind the actor before Starfield has evaluated the replacement rig; OSF now carries the last proven engine pose across that window by skeleton-joint identity and refuses to capture the replacement buffer until its own post-engine update, preventing a few-frame blend against the rig's rest pose.
- **Clips a pack registers through `clipLibrary` now appear in the browser for everyone.** They were being treated as the engine's own raw-clip debug entries and hidden unless **Show author details** was on, so a pack shipping a curated clip library and no scenes — Moods of Andromas, for one — loaded perfectly (no errors, clips found) and still showed nothing. Registered clips and the entries OSF derives automatically from a scene's stages share an id namespace; the catalog now marks a registration explicitly, and only the derived entries stay author-only. Scene ids are unchanged, so animation-wheel pins survive.

### Changed
- **The Animation Browser now stays open after launching a scene.** *After launching a scene* defaults to **Stay open** instead of collapsing to the live-controls bar, so browsing straight into a second scene no longer costs a re-expand. **Live controls** and **Close browser** remain available in Settings → Browser → Behavior, and an existing saved choice is untouched.

### Added
- **Scene and prop preview inspection in the Animation Browser.** Inspecting an animation opens a
  scrubbable, paused preview of the actual scene stage — cast placed, props attached, authored
  track lanes (cues / actions / sounds / camera) drawn on the timeline — and the stage strip
  switches stages without leaving inspection. Previews are side-effect-free and restore the cast's
  original positions on stop.
- **Studio Link preview inbox.** Enable **Studio Link** under Settings → OSF Animation → Advanced →
  Authoring to create `Documents\My Games\Starfield\SFSE\OSF\Studio Link`: an authoring tool can
  drop a request file there to play a raw `.af` clip or helmet transition preview on the player
  in-game and read the reply back, without a scene definition. It is off by default and fully stops
  its worker when disabled.
- **OSF UI 2.0.0 is now the minimum host.** The browser view targets the OSF UI 2.x runtime; older
  hosts show an update prompt on the browser's status line.
- **A stage can freeze on one frame instead of playing.** `"hold": true` parks a stage on its clips' last frame (`"hold": 0.4` on any normalized clip position), giving a scene a genuine static hold state — "carrying it", "waiting" — between two animations. Freezing the previous stage's own final frame costs nothing at the seam, where borrowing an unrelated idle re-poses the body to whatever that clip was authored against (with a `mask`, the masked part visibly pops to a different orientation). The clock does not advance, so a frozen clip never loops: `hold` is rejected alongside `loops`, `timer` is the only automatic way out, and otherwise the stage holds until a manual advance or an edge. Marks at or before the hold position fire once on entry, so an `action` at `at: 0` still runs. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **The Animation Browser can play a paused preview.** Inspecting an animation now offers ▶ / Ⅱ next to the frame steppers: the preview runs at authored speed and loops, with its temporary props stepping along, so an animation can be watched end to end without leaving inspection or starting the scene for real. It stays side-effect-free — no cues, sounds, cameras, or scene actions — and any scrub or frame step takes the transport back to paused.
- **Track lanes can be positioned by clip frame.** Any `cue` / `action` / `sound` / `camera` entry may use `"atFrame": 24` instead of `"at": 0.2424` — a zero-based clip frame at the 30 fps convention `.af` clips decode at. A frame is an absolute clip-local time rather than a proportion, so it stays on the moment you picked in your animation tool even if the clip is later re-exported at a different length, and it removes the divide-by-clip-length step from authoring by hand. Sound ladders accept `atFrame` for their position list too, and a per-hit override can still opt back into a fraction. `at` and `atFrame` are mutually exclusive, a non-integer or negative frame is rejected at load, and a frame past the end of its clip never fires. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **Props can be declared once per file and referenced by id.** A file may carry a top-level `props` registry mapping an id to a prop definition (`source`, `node`, and optionally `position`/`rotation`/`scale`); an `osf.prop.attach` then inherits it, using its own `prop` id as the lookup key — so a repeated attach collapses to `{ "at": 0.058, "type": "osf.prop.attach", "role": "player", "prop": "helmet" }`. Any key authored on the action still wins, `use` names a different template when two prop ids share one definition, and a template may be partial (carry only `source` and let each action pick its own `node`). An authored `source` replaces the inherited selector whole rather than merging into it, so overriding an `equippedArmor` template with a `form` works. Templates hold only those five keys — timing and dispatch are never inheritable — and a malformed one rejects its file while a dangling `use` rejects only its scene. Files without `props` are entirely unaffected. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **Mods can report the minimum OSF Animation version they require.** The copyable native header and Papyrus API now expose a shared reporter that compares semantic versions, deduplicates requests by consumer, surfaces an actionable HUD/System Health warning when OSF is too old, and retains a native fallback for OSF builds predating the reporter. See [`docs/API.md`](docs/API.md).
- **Synchronous native C++ scene-event callbacks.** Scene API ABI 1.3 lets SFSE plugins register a process-lifetime callback for scene begin/end, node, cue, and action events. Delivery occurs at the authored runtime mark before the equivalent Papyrus event is queued; registration is thread-safe, unregistration is quiescent, and one consumer's exception cannot prevent later callbacks. See [`docs/API.md`](docs/API.md).
- **Scenes can preserve equipped held items.** The new file/scene policy `clearHeldItems` defaults to `true`, retaining OSF's automatic cleanup of weapons, slates, tools, and other equipped non-apparel, while `false` lets partial-body equipment gestures leave those items untouched.
- **Scene-scoped render props.** Scene action tracks can now use `osf.prop.attach` to clone either a fixed form or a role actor's equipped armor, attach it to an actor node with a local transform, and address it by a scene-local id; `osf.prop.destroy` removes it at an authored handoff. Remaining props are ledger-owned and destroyed before scene-end dispatch on every termination path, with explicit load-teardown cleanup. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **Named bone masks for partial-body playback.** A scene role may set `"mask": "upperBody"` (or `arms`, `leftArm`, `rightArm`, `lowerBody`, `hands`) to drive **only** that bone set while Starfield's own locomotion keeps the rest of the body — the behavior-graph "equip/gesture while moving" look, instead of arms that keep running under an additive layer. Masked bones at full weight take the authored pose absolutely; `upperBody` feathers a spine seam (`C_Spine` 0.25 → `C_Chest` 1.0) so run/walk torso sway survives underneath, blending against an immutable post-engine base so repeated composes cannot creep toward a full override. Masks compose with `preserveBones` (still a hard exclusion) and with `"poseMode": "additive"` (the mask scales each bone's delta); unknown names are rejected at load with the known list. `poseWeight` is now honored in override mode too, as the documented persistent layer strength. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **An Import Workshop in the Animation Browser.** **IMPORTS** now treats pack repair as a first-class edit → reload → compare workflow. Every discovered `*.osf.json` is grouped by pack/folder and classified as clean, empty, missing assets, partial, or rejected, with exact authored/accepted/rejected scene counts and a plain-language result. Structured diagnostics carry stable codes, scene/node/role/clip context, repair hints, and missing-clip examples; technical counters stay behind disclosure. Authors can reload every scene/sound/gear registry and clip cache in place, see new and resolved diagnostics plus changed files, jump to content that did load, or copy the authoritative untruncated report to the Windows clipboard. Outcome tabs and full-text search keep large installations tractable. `OSFAdvanced.GetSceneLoadErrors`, the log, and System Health remain additive surfaces.

## [1.4.0] - 2026-07-30

### Added
- **Reference-relative additive pose playback for scene roles.** A role may set `"poseMode": "additive"` and an optional clamped `poseWeight` to layer an authored local-space gesture over Starfield's fresh locomotion/stance pose; omitted mode remains the existing absolute override behavior. Blend-in/out scales the layer, `preserveBones` remains an exact hard exclusion, stage changes refresh the skeleton rest reference, engine scale stays live, and repeated compose calls use an immutable post-engine base so deltas cannot accumulate. This is independent of scene anchoring and `inPlace`. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **The OSF Animation settings card is now organized into pages.** On an OSF UI new enough to render them, settings split into **General** (hotkeys), **Browser** (behavior, library, display), **Scenes** (launch defaults, scene gear), and **Advanced** (diagnostics) tabs instead of one long column. Older OSF UI versions keep showing the same settings as a flat list.
- OSF UI's consented bug reporter now recognizes OSF Animation as its report target when the Animation browser was active: the disclosure names this project, a bounded and locally redacted tail of `OSF Animation.log` is attached after consent, and the public issue is routed to the OSF Animation repository. The browser and settings schema now target OSF UI 1.5.0, the first release carrying that integration, so older hosts show the existing update warning instead of silently missing the reporting path.
- **The Animation Browser now presents one unified catalog of playables.** Individual library stages are direct animation rows instead of being buried inside playable “sets”; authored self-ending flourishes appear as Actions rather than a separate Emotes section; Scenes remain orchestrated playables; and pack/folder/set names are non-playable collection headers. Type facets, direct Play and Quick Access controls, a wider console, and a compact solo context bar make the catalog substantially denser. Launching a library row now pins playback to exactly that animation instead of continuing through the parent set.
- **The scene browser can now stay open when playback starts.** A new Interface > **Auto-Minimize** setting controls whether a successful browser launch collapses to the compact live controls; it defaults on to preserve the existing behavior.
- **Actors and furniture can now be selected by clicking them in the world.** Press PICK in Crew or Location, then click the visible object; a small drag still orbits the camera, and Escape cancels selection. SCAN remains available for crowded scenes and invisible AI markers.
- **World selection shows pick markers.** While actor PICK is armed, a bobbing diamond reticle floats over the head of whichever actor the cursor is on. Furniture PICK marks every pickable furniture nearby with a muted reticle, and the one the cursor is on lights up in accent. Both use the same acceptance geometry as the click itself — if a marker is hot, the click will select that target.
- **Problems now show up in OSF UI's System Health page** instead of only in the log. A scene or sound pack that could not be read gets a card naming the file and the first few reasons, so a broken pack stops being an invisible "why is this animation missing?" — one card per file, however many scenes it lost. Also reported: running on a Starfield version this build was not tested against, wheel pin customization that cannot be saved to disk, and screen fades disabling themselves after a game patch. Cards clear themselves when the condition goes away — fix a pack, run `OSF.ReloadScenes`, and its card moves to **Resolved this session** — and they ride along in System Health's **Copy diagnostic report**. Needs an OSF UI new enough to carry native ABI 1.7 (the release after 1.4.0); on anything older nothing changes and the log keeps every line, exactly as before. See [`docs/HEALTH_REPORTING.md`](docs/HEALTH_REPORTING.md).
- **OSF Studio**, a local-first web authoring workspace for OSF content. It imports and edits `*.osf.json` files with form and raw-JSON views, validation, undo/redo, browser-local drafts, and JSON export; previews GLB/GLTF and Starfield `.af` animation with orbit, scrubbing, animation selection, and skeleton-only rendering; and can create FK animation projects from `skeleton.rig`, key local bone rotations on a frame timeline, and export validated GLBs into its local clip library. Scene editing covers identity, policy, roles, placement, stages, timing, and clips, while graph scenes are preserved for JSON editing.
- **Curated clip libraries for content packs.** An `*.osf.json` file can now declare `clipLibrary` entries—with friendly names, tags, optional GLB animation ids, and slash-delimited folders—alongside scenes or by themselves. Each registered GLB/AF becomes a one-actor, in-place item under **Animations** without requiring a dummy scene; explicit metadata wins when the same clip is also referenced by a scene, missing clips are hidden and reported, and duplicate registrations are diagnosed. A file-level `folder` also organizes automatically exposed scene clips. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **Scene location selection in the animation browser.** Free-space scenes can launch at Cast A, the player, a selected cast member, about ten feet in front of the player, or a picked furniture/marker reference. Actor and furniture choices use their rendered world transform so attached ship/interior references resolve where they visibly are; front placement follows the current camera/player view; in-place scenes offer only their meaningful location; and duplicate choices are removed. Furniture-authored scenes still require a compatible furniture target.
- The name labels the browser tags selected cast members with in the world can now be turned off, from the browser's own Settings or OSF UI's OSF Animation card (Interface > **Actor name labels**, on by default). With them off the browser also stops asking the game where those actors are on screen.
- Trace logging now includes rate-limited scene heartbeats and launch-correlation details—runtime handle, playback id, cast, stage/time, clock owner, and sample/stamp ages—to distinguish a stopped animation update from a pose that stopped reaching the rendered skeleton.

### Fixed
- Saves that captured Starfield's persistent player AI-driven flag now repair it after the loaded world is active. The v1.2.0 persistence integration had moved cleanup entirely before normal named loads, allowing one affected save to remain non-controllable even after OSF was removed and reinstalled.
- Animation Browser collection headers can now be collapsed even when they contain the selected animation. Selection still opens its collection by default, but an explicit user collapse wins until that header is opened again.
- **The Animation Browser now opens on a useful pose instead of whichever emote arrived first.** Automatic selection waits for both catalog lanes and ranks photomode poses first, followed by other poses, animations, scenes, and actions; explicit user selections still stay put. Export-style names are also cleaned for display across Browse, the scene brief, Quick Access, launch notices, and live controls (`ArmsCrossed_Pose` → `Arms Crossed`, `LooseAnim_FormalApplause01` → `Formal Applause 01`) without changing scene ids or authored playback data.
- **World picking now behaves like sight.** A target that renders too small on screen to aim at (roughly beyond 50–60 m for an actor) gets no marker and can't be clicked — SCAN remains the tool for anything beyond sight. Distant targets no longer carry oversized invisible hit regions: the click acceptance shrinks with the target's on-screen size, so selecting someone far away takes deliberate aim instead of happening by accident "through" nearer geometry. When two targets overlap on screen, the front-most one (the one you actually see) wins the hover and the click. Markers are also no longer rationed by distance to the *player*: candidates are ranked front-most-first from the *camera*, and the crowd cap was doubled, so orbiting away from the player no longer leaves visible actors unselectable.
- **World picking no longer drifts away from the visible world.** Clicking an actor or furniture now selects exactly the target whose marker is lit under the cursor: the click resolves against the same marker geometry the browser renders, instead of running a second projection pass at click time that could disagree with what was on screen. The projection behind the markers also validates itself every poll — while the browser's orbit camera is live, the renderer camera is cross-checked against the pose OSF itself drives (switching to the correct camera when the renderer-storage slot goes stale), and a camera whose projection matrix disagrees with its own transform is rejected for that beat (markers briefly disappear and a warning is logged, rather than markers lying about where targets are). If picking still misbehaves, `OSF Animation.log` now says which camera check failed.
- **World actor selection no longer refuses some actors.** The click (and hover marker) acceptance region was first derived from the engine's culling sphere, then from the actor root node — both of which can drift away from the visible body (cull inflation from weapons and animation; root drift on actors OSF had animated). The hit region now spans two rendered bones (head to hips, feet extrapolated along the body axis), which are by definition where the body renders, covering standing and prone poses alike. A missed click logs the nearest candidate at debug level for diagnosis.
- **World actor picking stays armed between clicks.** Each pick used to disarm the mode — a miss or a successful add meant re-pressing PICK for the next actor, which read as the feature breaking. Actor pick now stays armed across hits and misses (click a cast member again to remove them; Esc or CANCEL finishes), while a furniture pick still completes on its single anchor. Adding a crew member also no longer folds the CREW panel shut, and the small ×/chip controls got comfortably larger hit targets.
- **Scene participants now return to their original position and heading after explicitly anchored scenes.** Furniture-launched and other world-anchor starts used to leave actors standing at the scene placement after playback ended. OSF snapshots each participant before an explicit anchor moves them and restores that transform on teardown, while guarding against a replacement scene or solo animation taking ownership in the meantime. Ordinary actor-relative scenes keep their existing end position.
- **Participants no longer keep held items through scene playback.** Scene start temporarily unequips slates, tools, drawn weapons, and other equipped non-apparel from every participant, then restores them on every scene-end path. This is independent of `stripActors`, so animation-library playback is covered too; worn apparel, scene gear, and furniture-owned props are unaffected.
- **Heads no longer remain distorted after a scene ends.** Face, eye, and morph nodes remain engine-driven throughout playback, and teardown now hands `C_Head` back to Starfield immediately instead of continuing to blend it while facial animation and equipment geometry resume. The rest of the body retains the normal smooth fade-out.
- **`scene_orbit` no longer engages aboard a ship in space.** The guard that already protected browser-drag orbit now also covers default and authored scene camera tracks, leaving the engine-owned ship camera active instead of driving an absolute world-space orbit against a moving/rebasing ship interior. Scene orbit remains available on landed ships.
- GLB animations exported without Starfield's `COM` bone no longer lift or stretch the actor. Poser-style files that place `C_Hips` and `C_Spine` directly under an unbound armature helper carry each body's roughly one-metre rest height in those tracks; OSF now removes that duplicated rest component while preserving the animation's actual pose offsets. Conventional COM-based GLBs are unchanged.

## [1.3.0] - 2026-07-24

### Added
- **Reusable role templates.** A multi-scene file's file-level `roles` key may now be an **object** — a file-local registry mapping an id to a reusable role template — instead of an array default cast. A scene instantiates a template inside its own `roles` array either as a bare id **string** or as an `{ "id": ..., ...overrides }` object, freely mixed with inline roles; both expand to ordinary roles at load, so matchmaking, `StartSceneRoles`, and track `"role"` refs are unchanged. Overrides merge JSON-merge-patch style (scalars replace, `filters`/`offset`/`equip` merge by key, arrays replace wholesale, `null` drops an inherited field), and repeated templates are auto-numbered into distinct runtime names (`["m", "m", "f"]` → `m`, `m2`, `f`) with explicit names reserved first. An array `roles` still means a default cast, and a scene that omits `roles` still falls back to clip-count inference — a registry is never an implicit cast. See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **`preserveBones` on a role** — an array of exact, case-insensitive rig bone names that stay engine-driven for that role. OSF omits only those bone slots while continuing to animate independently bound child bones, so a baked full-pose clip carrying an unwanted helper/root transform can be corrected without making the role gender-specific.
- **M/F indicators on actors in the scene browser.** Nearby scan rows, crew chips, and the `ROLES` map now carry the actor's sex tag next to the name, so a scene with gendered role slots can be cast without guessing. Creatures and any actor with no actorbase sex show no badge.
- Scene-browser start overrides (`STRIP`, `LOCK PLAYER`, `CAMERA`) are now **segmented pickers** instead of native dropdowns — Ultralight rendered the `<select>` popup layer underneath the surrounding brief controls, making the open list unreadable. `SPEED` now spans the full grid width.

### Fixed
- The scene browser no longer wedges at **Engine Offline** after a manual web-view reload. Readiness was gated solely on OSF UI's one-shot `runtime.ready` handshake, which a reloaded view has already missed; the view now also becomes ready on OSF Animation's own answer to the catalog/version request it sends on every mount.

## [1.2.0] - 2026-07-22

### Added
- **Cross-plugin persistence (cosave) API.** OSF now writes a small `.osf` sidecar next to each save and reloads it on load, so mod-added scene state survives save/load. Third-party SFSE plugins can register a client over the new native `OSFPersistenceAPI` (ABI 1.0, disk magic `OSFP`, format 1) to persist their own records through OSF's broker — versioned/CRC-checked records, atomic writes (a failed save preserves the previous sidecar), and FormID remap/delete resolution across load-order changes. See [`docs/PERSISTENCE_API.md`](docs/PERSISTENCE_API.md).
- Native free-camera access on controller: **R3** now mirrors middle mouse to toggle the engine `tfc` camera during a player scene. The input hook passes the pad through to native TFC even while the browser is visible, and toggling back restores the scene orbit/vanity posture underneath it.
- Clip-level debugging in the browser's **Animations** list: every distinct installed clip referenced by a non-library scene is auto-published as a one-actor entry (grouped by the scene file's `pack`, or its `*.osf.json` filename). Playing one runs just that raw clip in place — no strip, player lock, fade, role offset, or scene tracks. Generated vanilla/library scenes and emotes are excluded (they already populate Animations). See [`docs/SCENE_SCHEMA.md`](docs/SCENE_SCHEMA.md).
- **Custom-only** filter for the Animations library that hides vanilla-derived clips (id under `vanilla/` or tagged `vanilla`), so custom content isn't buried.

### Changed
- Player scenes with no explicit camera use `scene_orbit`, now as a native-assisted hybrid: OSF first enters Starfield's `tfc` path to retain its close-camera actor-mesh rendering behavior, then drives the camera transform itself for automatic cast framing, orbit, pan, height, and zoom controls. Explicit `"camera": "freefly"` still leaves movement entirely to the native TFC driver.
- Gamepad orbit-camera layout refined: the **left stick** now flies the orbit center **horizontally** (like WASD), **RT/LT** move it up/down, and **RB/LB** zoom in/out. (In 1.1.0 the triggers zoomed and there was no vertical control.)
- The scene browser view was rewritten from the legacy monolithic script onto a reducer/controller/selectors architecture with a mockable bridge and unit tests. No user-facing behavior change intended.
- Tested against OSF UI **1.3.0** — the status line's `UPDATE` badge now appears only on hosts older than 1.3.0 (was 1.2.0).

### Fixed
- Deferred scene callbacks (auto-end and timed marks) are now keyed by a stable `PlaybackId` instead of by participant identity, so a mark or end queued for one scene can no longer be delivered to a **replacement scene that reuses the same cast** after a rapid restart. A live scene also pins the exact registry definition it started with across a pack reload.
- Queued camera/control tasks are now gated across world loads so a task queued before a save-load can't fire against the freshly loaded world.

## [1.1.0] - 2026-07-21

### Added
- **Scene gear** — user-side scene equipment. Register any ARMO as gear in a slot (e.g. `belt`) via a `*.osfgear.json` anywhere under `Data/OSF/` (shippable by gear mods) or hand-edit `Documents\My Games\Starfield\SFSE\OSF\scene-gear.json`; a registered item **carried by a scene participant** is auto-equipped for the scene's duration (ledger-reversed on every end path, no inventory residue) — and if already worn, it's exempted from the default unequip instead, so pre-equipping it "just works". At most one item per slot per actor: a per-actor `overrides` entry in `scene-gear.json` picks between multiples (or `"none"` suppresses a slot), else a worn item wins, else stable order. A scene's authored role `equip` beats user gear for the slot it occupies. Global toggle: settings → Scene gear → **Auto-equip scene gear** (default on). Cast-manager UI for picking/registering gear lands in a follow-up.
- Gamepad camera control for the orbit camera: the **right stick** orbits (like mouse drag), the **left stick** flies the orbit center (like WASD), and the **triggers** zoom (RT in / LT out, like the wheel). Works in scene orbits and the browse orbit alike — the DLL polls XInput directly, so it keeps working while the browser overlay owns game input.
- Gamepad UI navigation while the scene browser is open: the **D-pad** moves focus (hold to repeat), **A** activates, **B** cancels the wheel / closes the browser — and the sticks stay on the camera. The view takes OSF UI's `osfui.gamepadRaw` grant (protocol 1.0) so the runtime's default mapping no longer routes the sticks into UI nav/scroll, and re-creates the D-pad/A/B half itself from raw `ui.gamepad` events.
- Scene browser: scenes are now organized into **collapsible per-pack groups**, so a big install (e.g. a compat pack spanning dozens of scene files) folds to a few headers instead of one endless list. Grouping keys on a new optional file-level `pack` field in `*.osf.json` (the content-pack display name — set the same string in every file of a pack to merge them into one group; see `docs/SCENE_SCHEMA.md`), falling back to the scene file's name. Groups auto-expand while searching, while the list is short, or around the selected scene; pack names are searchable. Catalog/library bridge payloads gain `pack` and `sourceFile` fields (additive).
- The scene browser's status line now also shows the installed OSF UI host version. If it predates the release this build was tested against (1.2.0), an amber `UPDATE` badge appears linking the [OSF UI Nexus page](https://www.nexusmods.com/starfield/mods/17711) — clicking it in-game opens the page in your system browser (OSF UI's `osfui.openModPage` command: the URL is hardcoded in OSF UI, nothing crosses the bridge), and the SFSE log gains a matching warning.

### Changed
- The status line is now compact (`OSF 1.1.0 · UI 1.2.0`) so it can't push the header layout down; the full identity moved to its tooltip. The plugin version no longer renders a trailing unused build field (`1.0.0.0`).

### Fixed
- Scene-browser camera handling aboard ships. Opening the browser from the **pilot seat** no longer force-switches to the on-foot third-person camera (a stranded "staring at your own hull / void" view that nothing restored — the cockpit registers as first person to the engine, so the browser's can't-see-yourself kick fired on seated pilots too; it now skips them). Closing the browser (or any scene camera ending) now returns a pilot to the **cockpit or whichever ship view they had**: camera baselines are captured as the exact engine state and engine-owned states are handed back directly, because the on-foot first/third-person re-entries silently bail for a seated pilot. The post-load leaked-camera recovery restores the cockpit for pilots the same way.
- The browse orbit no longer engages while **aboard a ship in space** (dragging the world area simply does nothing there; landed ships orbit as before). The orbit drives the camera in absolute world coordinates captured once at engage, and space cells re-base/move under the ship interior — the result was the camera violently spinning around the hull.

## [1.0.0] - 2026-07-20

### Added
- Global hotkeys, configured in OSF UI's in-game settings menu (OSF Animation card → Hotkeys): open scene browser and open emote wheel. Rebindable in-game with conflict badges; the wheel defaults to `B` (free in vanilla, the emote-wheel convention key), the browser stays unbound (F10 — the OSF UI console toggle — already opens it). Delivered by OSF UI's HotkeyService (bridge ABI 1.4), so keys never fire while the console is open or a text field is focused.
- Settings moved into OSF UI's settings menu (schema registered at runtime over the native bridge): log level, stage-transition debug popups, and first-run hint. Values persist in `Documents\My Games\Starfield\OSFUI\settings\osf.json`. **`Data/OSF/settings.json` is no longer read** (a one-time log warning fires if one is present); with OSF UI absent or too old, defaults apply and hotkeys are unavailable.
- Emote wheel: the `openWheel` hotkey opens the browser view in a radial mode listing solo scenes tagged under a prefix (default `player.emote.*`, so the immersion pack's emotes appear out of the box; `openWheel:<prefix>` overrides). Picking plays the emote on the player — or on the crosshair NPC captured at open time (dead / in-combat / non-human targets fall back to a player-only wheel) — then closes. Cancel with Esc, right-click, or the center hub. Adds the generic `osf.requestClose` bridge command (the view asks the host to hide it).
- Immersion content pack (`Data/OSF/immersion/`, pure JSON over vanilla `.af` clips): self-terminating `player.emote.*` scenes (wave, what's up, hands on hips, arms crossed, data slate) for the emote wheel. Documents the well-known tag contract in `docs/SCENE_SCHEMA.md`.
- Browse orbit: dragging the world area of the scene browser now always steers an orbit camera. With no scene camera live (no scene running, or a `camera:"none"` scene like an emote), the first drag engages an orbit around the player's scene cast (or the player); closing the browser restores the previous view. Previously the drag only worked while a `scene_orbit` scene was playing — with the browser open, OSF UI freezes all game input, so the camera was otherwise immovable.

- Badge icon in OSF UI's Mods surface: the rail entry and Home cards now show the OSF playback-curve mark (`views/osf/osf-icon.svg`, schema `icon` field — a tiny-size cut of the branding emblem, bolded to stay legible at ~30px) instead of the "OA" initials monogram. Needs an OSF UI new enough to know the field; older versions ignore it and keep the initials.

- Emote-wheel pinning: a `◇ PIN TO WHEEL` toggle in the scene browser's brief puts any solo authored scene on the emote wheel (pinned rows show a ◆ marker). With pins present the wheel shows exactly them, in pin order; with none it falls back to the `player.emote.*` tag pool as before. The list persists DLL-side in `Documents\My Games\Starfield\OSF\wheel-pins.json` (account-global; pins whose pack is uninstalled are kept dormant and revive on reinstall). New bridge command `osf.animation.wheel.pin {sceneId, pinned}`, answered by a catalog re-push with per-scene `pinned` order.

### Removed
- SAF backwards-compatibility shim (the opt-in `SAF.pex`/`SAFScript.pex` FOMOD component from 0.2.0) and its supporting internals: the non-public `OSFCompat` natives, the Activate-key redirect in the input hook, and the FOMOD "Compatibility" install step. SAF-targeting content should use the real SAF, or be ported to the OSF API.

### Changed
- Emote-wheel ring geometry is now count-adaptive: near-circular for a handful of emotes (the shipped pack's ~5 no longer stretch into a flat oval), widening toward the old 12-slice ellipse as the ring fills.
- Vanilla library packs now exclude **partial-coverage layer clips** (real tracked bones < 85% of the rig, measured from the `.af` index atlas — e.g. cover-lean or `*_idlepartialbody_*` layers with 5-25 of 82 bones): played standalone they T-pose every untracked bone. ~1,700 of ~14k clips dropped from the browsable catalog; regenerate with `generate_vanilla_packs.py --include-partial` to re-add them tagged `"partial"`.
